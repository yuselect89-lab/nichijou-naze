# 日常のなぜ？｜AIコンテキスト節約・工程間引継ぎ

更新：2026-11-01。この文書は読み方と差分引継ぎを最適化するもの。**制作仕様を変更しない**。最優先は `production-lock.json`、承認済みの素材と台本・音声、G1/G2/G3の既存QC。

## 役割別の読み込み

| 担当工程 | 毎回必要 | その工程でのみ追加 |
| --- | --- | --- |
| Codex：素材制作 | `AGENTS.md`、`production-lock.json`、対象EPの確定カット割・納品仕様、`npm run preflight` の結果 | `PRESENTER_DIRECTION.md`、`TYPOGRAPHY_4_PRINCIPLES.md`、`VISUAL_QUESTION_DIRECTION.md`、素材台帳の対象ID/版・依存だけ |
| Work：本編組立 | `production-lock.json`、対象EPのLOCK、実素材一覧、同梱SHA、`WORK_HANDOFF.md`、`npm run preflight` の結果 | 映像構成の該当箇所、音・字幕・エンドカード・G3確認に必要な規則だけ |
| G1/G2/G3 QC | そのQC対象となる確定版、確認結果の証拠、適用する基準 | 不一致箇所と根拠のみ。旧版履歴の全文は原則不要 |

`AGENTS.md` の各「必ず読む」対象は**当該工程で読む**。一度確認済みで変更されていない文書を、同一セッションのツール呼び出しごとに全文再送しない。Codex・Workへは指示全文を繰り返し転記せず、正本へのパスと短い差分・LOCK IDで渡す。読み飛ばすことが制作ゲートの免除になるわけではない。

## 機械確認と差分引継ぎ

`node tools/handoff-diff.mjs <EP納品フォルダ> --write <初回マニフェスト.json>` で、対象ディレクトリのファイル名・サイズ・SHA256を機械で保存する。再納品・微修正時は `node tools/handoff-diff.mjs <同じフォルダ> <前回マニフェスト.json> --write <新マニフェスト.json>` により、**新規・変更・削除されたファイルだけ**をAIに提示する。未変更ファイルの内容を再解析しない。ただし、**過去のQCがPASSであることも確認できた未変更ファイル**に限り、同工程の同一内容レビューを省略できる。

- 不明／HOLD／未PASSの素材は、ハッシュが同じでも審査対象のまま。
- 差分がなくても本編組立後の実MP4 G3や、版・依存・権利・長さの照合は省略しない。
- 共通素材は既存の `node tools/library.mjs search/preflight/check` を優先し、ハンドオフ差分ツールを既存の素材台帳の代わりにしない。
- 途中のプレビューは変更部分の静止画コンタクトシート、必要なら短い該当クリップ。**画の品質が判断できない場合は実画像・実MP4を確認**する。
- 音声ファイルの追加提出をユーザーへ求めず、未検証の音声を検証済みと称しない。
- 納品では、完成物への正しいパス、適用LOCK、SHA256、既存QCの判定、未解決事項を短く示す。全ファイルの内容説明や不要な長文作業ログを入れない。

## ZIPと責務

素材担当のCodexは**本編完成動画を作らず**、承認済み設計の素材と必要なモーション、ソース、QC証拠と差分マニフェストを渡す。本編編集のWorkはそれを使って1本の動画に仕上げる。素材の再生成は対象カットで欠落・破損・不適合が確認できたときだけ。固定帯、進行バー、字幕は本編側で一度だけ合成する。
