これ以外の文面（旧README、過去のChatGPT指示、チャットメモリ）は、上記と矛盾する場合は**採用しない**。

## 必須のゲート

Codex、ChatGPT Work、その他編集担当は、制作開始・素材引渡し・ラフ/最終書き出し前に専用リポジトリの最新コードを取得して以下を実行。

```bash
cd /workspace/nichijou-naze
npm run preflight
npm test
```

`npm run preflight` が失敗した場合は正式帯の確認ができていない。映像の書き出し・納品・似た素材での代用はせず、エラーを報告する。

`npm run render -- ...` と `node tools/package.mjs` にも事前検査が組み込まれている。シリーズの本編コンポーネントも承認済み帯の固定パスを参照する。**GitHub外の独立FFmpeg合成や古い納品ZIPではこのゲートは自動では作動しない**ので、Work側でも上記コマンドの実行結果を必須納品記録とする。

## 別の正式帯へ変更する場合のみの手順（現行は登録済み）

1. EP002 V4などの**ユーザー承認済み完成版の正しい元画像ファイル**を入手し、見た目と文字組みを承認記録と照合する。静止画からの想像による新規作画を正本としない。
2. 元PNGのコピーを `public/series/approved/opening_banner.png` に配置する。元データは保持。不要な加工をしない。
3. ローカルで `sha256sum public/series/approved/opening_banner.png` を実行。結果を `production-lock.json.banner.sha256` に登録し、照合が完了したときにのみ `status` を `APPROVED` に変更。
4. `library-registry.json` の帯参照も承認済み原本と同期し、旧SHAを利用禁止の履歴として残す。
5. `npm run preflight` と `npm test` を通す。
6. 実際に出力したMP4の冒頭を、承認済み完成動画の該当フレームと目視比較して確認。字幕や図解の領域との重なりも検査。**原本のハッシュ一致のみで最終動画の見た目まで保証できるわけではない。**
7. 画像のデザインを変える場合はユーザー承認・新バージョン・新SHA256・再QCを必要とする。無断差替え禁止。

## その他の制作固定値

- **問いの視覚的な見せ方**：新規映像設計・G2・G3の標準は `docs/VISUAL_QUESTION_DIRECTION.md`。正式黄色帯を変えず、問いの説明文を単純拡大するのではなく実物・動作・短いテキストで表現する。台本・VOなどのLOCKは無断変更しない。
- 字幕：読点「、」は削除、句点「。」は残す。台本やVOを勝手に変えない。
- 黄色帯・全編の単一進行バー・字幕：完成本編でそれぞれ1回だけ合成。素材単体で二重合成しない。
- キャラ：かわいい女の子が解説する役割。問いと結論は表情の読める大きさで、仕組みの核心では図解を優先。
- EP素材：登録台帳を検査→再利用／改修／新規を選択→新規候補はEP内でQC後に登録。原本や過去動画を上書きしない。
