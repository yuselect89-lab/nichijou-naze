# 日常のなぜ？｜映像品質PDCAの通常制作導入案

2026-10-23 / 導入先: `yuselect89-lab/nichijou-naze` / 状態: **試験運用・未承認**

## 目的

EP006だけを何度も直すのではなく、新しい題材の**初稿から**分かりやすさとビジュアル品質を再現する。制作を早く終えるために仕様や実物QCを省かない。ユーザーのレビューを、基本的な不具合の発見作業にしない。

この文書は `production-lock.json`、`AGENTS.md`、`docs/PRODUCTION_LOCK.md`、`docs/VISUAL_QUESTION_DIRECTION.md`、`docs/PRESENTER_DIRECTION.md` を変更・上書きしない補助基準。矛盾があれば正式な正本を優先する。

## 実際に得られたEP006の知見

- 冒頭: 日常の入浴体験を認識できない不自然なCG指先は不適切だった。実写・フォトリアル素材など、題材の現象を直感的に認識できる表現を選ぶ。**本編のCG・3Dは禁止しない**。何を理解させるかで手段を選ぶ。
- 科学解説: A7で理解可能になった「血管が細くなる→内部の張りが減る→表面に浅い折り目ができる」という順序を固定し、造形の試作と動きの試作を分けた。
- 不採用例: A9の過剰な注目リングは視線を散らした。A11〜14では不自然な断面端、余分な血管・白帯、変形の不連続を発見し修正した。これらを全EP共通の禁止事項にせず、**描く対象の意味を損なう装飾・破綻は不採用**という判断方法を再利用する。
- 全編V5→V6: 意図したカメラ移動が実際の映像に出ていなかった。予定表でなく、実動画の同じ範囲を測って再評価した。
- A15/V6の技術QC成功は映像品質や外部G3合格ではない。外部QC、視聴者の評価、次EPでの再現性は別。

## 実装担当と具体的なタイミング

1. **ChatGPT（企画・設計）**：台本と音声のLOCKを確認し、冒頭に提示する現象、表現手段の根拠、女の子の役割、核心の変化をカット別に決める。G2前に視覚的な候補を比較して弱い案を捨てる。
2. **Codex（G2通過後の素材制作）**：既存ライブラリを検索・verifyし、使える版を再利用。不足する核心動作をまず数秒で実レンダーして確認。失敗した場合は原因と不採用カットを残し、原本を上書きしない。有料生成は承認なしで実行しない。
3. **ChatGPT Work（ラフ合成）**：承認済み帯、単一進行バー、字幕、LOCK済みVOを親本編で一度ずつ合成。仕様にないBGM/SEを足さず、最終の見え方を360pxと通常サイズで確認する。MP4の実ファイルを保存。
4. **自動技術検査（書き出し直後）**：`npm run preflight` と `npm test` に加え、`tools/visual_pdca_qc.py` を候補MP4へ実行する。ファイル形式・全デコード・原本ハッシュ・元音声とのAAC同一性・字幕SRTとLOCKの文字・設計された部分の映像変化を記録する。画面上の焼き込み字幕や美しさはこれだけでは確認できない。
5. **外部QC（Gemini G2/G3）**：設計段階G2と完成ラフG3は独立した実物評価。実際の結果を受け取るまでPASS扱いしない。適用可否の最終判断はユーザーの承認と別物。
6. **次の2〜3EP**：各EPの初稿で「仕様違反件数、初稿の必須修正件数、G2/G3判定、ユーザーが初歩的な欠陥を指摘した件数」を測り、通常制作で再現できたかを検証する。EP006だけで再現性を証明したとは言わない。

## 実行コマンド（例）

まず正式な制作リポジトリ内で
```bash
npm run preflight
npm test
python3 tools/visual_pdca_qc.py --config episodes/EPXXX/visual_pdca_case.json --out episodes/EPXXX/visual_pdca_report.json
```

`episodes/EPXXX/visual_pdca_case.json` は `examples/visual-pdca-case.example.json` から作る。相対パスは**設定JSONの所在からの相対パス**。映像の意図的な動きがない区間に運動量閾値を設けてはいけない。各閾値は試作の実物を基準にカット個別に決める。

## 解釈上の注意

- `automatic_pass: true` は技術検査のみの成功。レポートの `overall_status` は必ず `HOLD` のまま。動画の完成PASSは別手続き。
- `audio_unchanged` はAACトラック同士のエンコード同一性の検査。最終ミックスを調整する場合は厳密一致せず、元音声の波形・同期・音量を別手順で確認。
- SRTの文字比較は焼き込み字幕が正しく表示された証明ではない。音声あり・なし・360pxで実物を見る。
- 初稿レビューで失敗を発見した場合、原因と修正を追記。根拠なく動画ごとの仕様を全EPへ一般化しない。
